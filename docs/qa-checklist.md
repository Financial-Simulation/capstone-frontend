# 화면 점검 목록

실제 v1.7 백엔드로 화면을 눌러 보며 확인하는 목록이에요. 발표 리허설 전에 한 번 다 보고, PR 전에는 바꾼 부분만 봐요.
숫자는 팀 정답 파일과 같아야 해요 (같은 seed라서 백엔드가 켜져 있으면 정확히 같은 숫자).

## 준비

- [ ] 백엔드 `./gradlew bootRun`, 프론트 `npm run dev` (발표 리허설은 `npm run build && npm start`, README '발표 데모')
- [ ] `/dev` → API 점검 `전부 실행`: 17개 모두 기대대로 (백엔드가 v1.7인지)
- [ ] `/dev` → 정답 파일 대조 `전부 대조`: `같음 55 / 55`
- [ ] 휴대폰 폭: Chrome 개발자 도구(⌥⌘I) → 기기 모드(⇧⌘M) → 390 × 844

## 00 시작

- [ ] 처음 들어오면 '시뮬레이션 시작하기' · '예시 결과 보기'
- [ ] 입력이 남아 있으면 '이어서 할까요?'(이어서 하기 / 새로 시작), 기준 달이 지났으면 '기준 달을 이번 달로 바꿀까요?'

## 01-1 나와 소득/지출

- [ ] 빈 채로 '다음' → 빈 칸이 빨갛게, 첫 칸으로 이동
- [ ] 칸 아래 범위 안내(19~39세 · 0~10년 · 1만~3,000만 원)와 범위 밖 값의 문장
- [ ] '더 정확하게 넣기': 세전 연봉이 월 실수령액 × 12보다 작으면 세전 연봉 칸 아래 오류 (접혀 있으면 펼쳐서 그 칸으로)
- [ ] '그중 월세'가 고정지출보다 크면 그 칸 아래 오류
- [ ] 지출이 소득 이상이면 경고 모달 ('수정하기' / '그대로 진행')

## 01-2 자산/대출/저축

- [ ] 대출 카드: 종류를 고르면 평균 금리, 칸이 다 차면 월 상환액 미리보기
- [ ] 매달 남는 돈 · 청년미래적금 안내가 입력하는 대로 바뀜
- [ ] 매달 모자라면 경고 모달

## 02 목표 · 03 시나리오

- [ ] 목표 시점은 기준 연월부터 1~10년만 고를 수 있음, 이미 목표 이상이면 안내 모달
- [ ] 예정된 일 5종: 켜면 '언제'와 기본 금액. 이직은 '−90~+200%, 기본 +10%' · '0~24개월, 기본 2개월'

## 04 결과

- [ ] 계산 중 → 결과 (5초가 넘으면 '평소보다 오래 걸리고 있어요')
- [ ] 예시 S1과 같은 입력이면 58.0%, 첫 문장에 4,440만 원
- [ ] 그래프: 누르거나 화살표 키로 달 옮기기, '표로 보기'
- [ ] 위험 카드 5장, 세금 카드 5장과 안내 문장 (월세 안내의 링크 → 01-1 '그중 월세' 칸)
- [ ] 어디에 얼마나: 범위 밖 값 오류 · 일반 적금(나머지) · '지금 계획과 비교하기' · '가장 좋은 배분 찾기'(누르는 동안 '찾는 중…', 1~3초) · '이 배분으로' → 다시 계산하고 맨 위로
- [ ] 이 숫자는 얼마나 믿을 수 있나요?: 진행률 → 띠와 문장
- [ ] 계획 바꿔 보기(맨 아래 버튼): 미리보기 · 비교에 담기(새로고침해도 남음) · 담은 계획 비교 · 결론이 같은지 · 접기
- [ ] 내 입력값과 적용 가정: 펼치면 근거 표
- [ ] 위쪽 '리포트 저장' → 리포트 → '인쇄 · PDF로 저장' → 인쇄 창의 대상 'PDF로 저장' → 머리글 · 버튼 없이 A4로 나옴 (Chrome · Safari)

## 04-E 예시 결과

- [ ] 위쪽에 파란 '예시' 배너, 예시 세 명 바꿔 보기
- [ ] 세금 · 어디에 얼마나 · 가능성 범위 · 계획 바꿔 보기 · 리포트 저장이 없음 (내 계획에만 있는 블록)
- [ ] '내 정보로 시작하기' → 저장된 입력이 있으면 '이어서 할까요?'

## 실패 · 느림

- [ ] 백엔드를 끄고 결과 → '백엔드가 응답하지 않아요' + '다시 계산' ('입력 확인하기'가 아님) → 백엔드를 켜고 '다시 계산'
- [ ] 입력 화면에서 백엔드가 꺼져 있으면 위쪽 안내 + '다시 시도' / '검사 없이 다음으로'
